* [mcp] shutting down no longer waits on an attached MCP client. The SSE stream behind `GET /_overcast/mcp` and the legacy `/_overcast/mcp/sse` selected on the request context alone, so the only thing that could end it was the client disconnecting — and an attached MCP session that has simply gone quiet never does. Because a graceful shutdown waits for in-flight handlers, one attached client was enough to hold `overcast` open until it was killed. The stream now takes the same pre-shutdown channel the emulator's other long-lived handlers have always taken, and ends when the emulator does; a client that wants the stream back reconnects, and `Last-Event-ID` resumes it where it left off
