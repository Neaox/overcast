* [mcp] shutting down no longer waits on an attached MCP client. A long-lived MCP stream selected on the request context alone, so the only thing that could end it was the client disconnecting — and an attached MCP client that has simply gone quiet never does. Because a graceful shutdown waits for in-flight handlers, one attached client was enough to hold `overcast` open until it was killed. The stream now takes the same pre-shutdown channel the emulator's other long-lived handlers have always taken, and says so before it goes: a `subscriptions/listen` stream is closed with the empty result that marks an orderly end, so a client can tell a shutdown from a dropped connection and decide whether to reconnect
