* [router] a request signed for one service (e.g. OpenSearch, MSK) that lands on a path modeled for a different real AWS service now gets that service's own scoped-credential 403 (InvalidSignatureException naming the expected signing name), matching what AWS answers when a credential scope names the wrong endpoint — instead of falling into S3's bucket/object wildcard and returning a nonsensical NoSuchBucket/NoSuchKey. Unsigned traffic, S3's own traffic, and a scope that is not a real AWS signing name are unaffected.
