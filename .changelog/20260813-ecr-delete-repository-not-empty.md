*! [ecr] `DeleteRepository` refuses a repository that still holds images unless `force` is set, answering `RepositoryNotEmptyException` (HTTP 400) as AWS does. It previously ignored `force` entirely and answered 200, taking every image in the repository with it — the guard is the only signal a caller gets, so a teardown that meant to be stopped was told it had done the right thing instead. An image that arrived by `docker push` counts too: the registry is swept before the check, the same way `ListImages` sweeps it
  migration: a script that deletes a repository holding images has to pass `--force` (`force: true`), which is what the same script already needs against real AWS
