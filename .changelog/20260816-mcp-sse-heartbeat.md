* [mcp] a long-lived MCP stream now sends a keep-alive every 15 seconds while it is idle, so a quiet stream is no longer indistinguishable from a dead one. Nothing flows on a `subscriptions/listen` stream between notifications, and a stream that says nothing for minutes at a time is what proxies and client idle timeouts close underneath you — and what stopped the emulator noticing a client had gone, because it never attempted a write to find out. With the `ping` utility method removed by MCP revision `2026-07-28`, this is the only liveness mechanism the stream has left. The keep-alive is an SSE comment line, the shape the specification points at for a long-lived stream: a line beginning with a colon carries no event data, and clients ignore it rather than treating it as a message. Nothing is added to the protocol and no JSON-RPC message is invented. The interval matches the emulator's two other SSE endpoints
