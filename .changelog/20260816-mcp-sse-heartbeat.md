* [mcp] the SSE stream now sends a keep-alive every 15 seconds while it is idle, so a quiet stream is no longer indistinguishable from a dead one. Nothing flows on `GET /_overcast/mcp` between server-initiated messages, and a stream that says nothing for minutes at a time is what proxies and client idle timeouts close underneath you — and what stopped the emulator noticing a client had gone, because it never attempted a write to find out. The keep-alive is an SSE comment line, the shape the MCP specification points at for a long-lived stream: a line beginning with a colon carries no event data, and clients ignore it rather than treating it as a message. Nothing is added to the protocol, no JSON-RPC message is invented, and the comment carries no event id, so a client resuming with `Last-Event-ID` still resumes from the last real message. The interval matches the emulator's two other SSE endpoints
