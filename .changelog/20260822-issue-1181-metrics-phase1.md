+ [lambda/cloudwatch] emulated Lambda functions now automatically publish the AWS-native CloudWatch metrics real AWS publishes (Invocations, Errors, Duration, Throttles, ConcurrentExecutions), so a CloudWatch alarm on e.g. AWS/Lambda Errors evaluates and fires end-to-end instead of silently never triggering. Recorded once per invocation at the shared outcome boundary every invocation path (sync, async, function URLs, event source mappings) already funnels through; GetMetricStatistics, GetMetricData and ListMetrics return the automatic series alongside custom PutMetricData data. New internal/metrics package (Recorder/Observation/Bucket types, sharded in-memory hot path, dedicated SQLite tables where available, one-hour retention) backs the substrate for future SQS/SNS/DynamoDB/API Gateway metrics. OVERCAST_SERVICE_METRICS=auto|enabled|disabled controls collection (default auto).
