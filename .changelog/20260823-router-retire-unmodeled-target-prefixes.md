*! [router/appregistry/efs/eks/scheduler] AppRegistry, EFS, EKS and Scheduler no longer answer `POST /` for an `X-Amz-Target` header (`AppRegistry.`, `EFS.`, `EKS.`, `Scheduler.`) or a Smithy RPC v2 label (`/service/<name>/operation/<op>`) — a wire the pinned models never gave these restJson1 services and no real SDK ever sends. Both doors now answer the same honest "unknown operation"/"unsupported protocol" error any nonsense request gets, never a 200.
  migration: address these four services only at their modeled REST bindings (the paths already documented in docs/services/), the same way any AWS SDK or the `aws` CLI reaches them today.
