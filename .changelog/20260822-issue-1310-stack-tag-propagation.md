+ [cloudformation] `AWS::CloudTrail::Trail`, `AWS::Transfer::Server`, `AWS::Transfer::User`, `AWS::IAM::ManagedPolicy` and `AWS::IAM::InstanceProfile` now merge a stack's own tags onto the resources they create, and reconcile a stack-tag-only change on update, matching every other propagating resource type
~ [cloudformation] `AWS::IAM::Role` and `AWS::IAM::User` now also merge the stack's own tags, instead of only their own resource-level `Tags`
* [cloudformation] `AWS::Transfer::Server` no longer forces replacement when only its `Tags` change; it reconciles them via `TagResource`/`UntagResource` in place instead, same as every other resource type that reconciles tags without replacing
* [cloudformation] `AWS::DynamoDB::Table`, `AWS::SSM::Parameter` and `AWS::StepFunctions::StateMachine` now reconcile their tags when only the stack's tags change and the resource's own template properties do not; a stack-tag-only update previously left their tags unreconciled even though the resource's own tag-reconciliation code was already correct
