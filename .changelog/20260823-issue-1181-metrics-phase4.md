+ [metrics] Lambda now records its asynchronous-invocation CloudWatch metrics (phase 4 of the service-metrics substrate, #1181): `AsyncEventsReceived` for every accepted Event invocation, `AsyncEventAge` per retry attempt, `AsyncEventsDropped` when an event outlives its `MaximumEventAgeInSeconds`, and `DeadLetterErrors`/`DestinationDeliveryFailures` when a failed invocation's dead-letter or destination delivery itself fails.
+ [metrics] Automatic service metrics (Lambda, SQS, SNS, DynamoDB, API Gateway) now survive a restart on `OVERCAST_STATE=wal` and every `-tags nosqlite` build — the one gap every earlier phase of the service-metrics substrate disclosed. `OVERCAST_STATE=memory` is unaffected: there is nothing for it to restart into.
+ [web/sns] SNS topic pages now have a Monitor tab showing the AWS/SNS metrics the emulator already records automatically (phase 2 of the service-metrics substrate, #1268) as charts — messages published, publish size, and notification deliveries/failures — over 1h/6h/24h/7d/30d ranges, through `GET /_overcast/sns/topics/{topicName}/metrics` and the BFF proxy `GET /api/sns/topics/{topicName}/metrics`.
+ [web/dynamodb] DynamoDB table pages now have a Monitor tab showing consumed read/write capacity as charts, through `GET /_overcast/dynamodb/tables/{name}/metrics` and the BFF proxy `GET /api/dynamodb/tables/{name}/metrics`.
