* [mcp] Cancelling an in-flight request over HTTP could panic the connection serving it. The `notifications/cancelled` event was written to the cancelled request's response stream only after the request had been released, so the response could finish — and net/http reclaim the connection — while the write was still on its way. The notification now goes out first, while the response provably cannot end; a request that finishes of its own accord in the same instant has the late write dropped rather than made
