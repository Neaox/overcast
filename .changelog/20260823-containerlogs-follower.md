~ [ecs] a task's `awslogs` output is now followed with reconnect, exact de-duplication and batched CloudWatch writes, so a daemon hiccup no longer costs the rest of a task's logs. The pump behind the `awslogs` driver used to open one log stream and scan it: when that connection broke — which is likeliest under exactly the load that makes a task worth reading the logs of — it ended, silently, and everything the task printed from that moment on went nowhere. It now uses the same follower Lambda's function output goes through, which re-opens the stream and resumes from where it left off. Resuming is by timestamp, the only resume the daemon offers, so the lines sharing that instant come back a second time; they are counted and dropped rather than written twice, including the several a runtime emits within one nanosecond when it prints a traceback. Lines also go out in batches rather than one CloudWatch write each, an oversized line is truncated instead of buffered without limit, and the timestamp on each event is the container's own — the previous code fell back to reading the host clock, which put a line's arrival time on it rather than the moment it was printed.
