*. [mcp] a client can open one long-lived stream with `subscriptions/listen` and say on it exactly which notifications it wants. MCP revision `2026-07-28` replaces both the standalone GET stream and `resources/subscribe` with this: the request carries a filter naming the notification types and the resource URIs of interest, the server acknowledges with the subscription's id before sending anything else, and every notification on the stream carries that id so a client running several can tell them apart. Types the client did not ask for are never sent, and request-scoped notifications — progress and log messages — never appear here, because those belong to the response stream of the request they relate to. The stream sends a periodic keep-alive comment and ends cleanly when the emulator shuts down, so a client can tell an orderly close from a dropped connection. Existing clients are unaffected: `resources/subscribe` and the GET stream continue to work until a later change retires them
