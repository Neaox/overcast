* [athena] CreateWorkGroup stopped dropping Tags (#1196); tags are validated and applied at create time, readable via ListTagsForResource without a follow-up TagResource call. The legacy JSON1.0/1.1 handler now delegates to the CBOR typed path instead of duplicating it.
* [eventbridge] CreateEventBus and PutRule stopped dropping Tags (#1196); PutRule merges tags with whatever the rule already carries, matching AWS documented behavior. Both legacy handlers now delegate to their typed counterparts instead of duplicating them.
* [firehose] CreateDeliveryStream stopped dropping Tags (#1196); the legacy handler now delegates to the typed path instead of duplicating it.
* [ssm] PutParameter stopped dropping Tags (#1196); tags apply only when the call creates a new parameter, matching AWS documented behavior that Tags cannot update an existing parameter (use AddTagsToResource for that). The legacy handler now delegates to the typed path.
* [rds] CreateDBInstance, CreateDBCluster and CreateDBSubnetGroup stopped dropping Tags (#1196); tags are validated and stored in the existing ARN-keyed tag namespace, the same one AddTagsToResource writes to.
* [elasticache] CreateReplicationGroup stopped dropping Tags (#1196); CreateCacheCluster and CreateServerlessCache already applied tags at create. Both the Query-XML handler and its independent CBOR typed path are fixed.
* [stepfunctions] CreateStateMachine stopped dropping tags (#1196); the request previously modeled no tags member at all. Fixed a pre-existing bug surfaced while unifying the legacy and typed paths: the typed path hardcoded the account default region instead of the requests actual region when minting the state machine ARN.
* [cognito] CreateUserPool stopped dropping UserPoolTags (#1196); the request previously modeled no UserPoolTags member at all. The legacy handler now delegates to the typed path instead of duplicating it.
* [ecs] CreateCluster and CreateService stopped dropping tags (#1196); RegisterTaskDefinition already stored its tags. Both legacy handlers now delegate to their typed counterparts, which is where the fix lives.
* [ec2] CreateVpc, CreateSubnet, CreateSecurityGroup, CreateInternetGateway, CreateRouteTable, CreateVpcEndpoint, CreateVpcPeeringConnection, CreateNetworkInterface and CreateKeyPair stopped dropping TagSpecification.N (#1196); RunInstances, CreateNatGateway and CreateVpnGateway already honored it. CreateVpcEndpoint and CreateVpcPeeringConnection previously carried no tag set in any response at all and now do.
