[ec2] Create-time `TagSpecification.N` is honoured on every create AWS models with one, whichever decoder reads the request. `CreateVpc`, `CreateSubnet`, `CreateSecurityGroup`, `CreateInternetGateway`, `CreateRouteTable` and `CreateNetworkInterface` route through the generated typed operation registry, and their typed request shapes declared no tag specification at all — so a CDK deployment, which tags everything at create rather than with a follow-up `CreateTags`, got resources with no tags in the create response, none on `DescribeTags`, and no error to say so. A tag the model refuses — a reserved `aws:` key, an over-long key or value, more than fifty of them — now fails the create on that path too, rather than creating the resource and silently discarding the tag.
* [ec2] `CreateSecurityGroup` returns the `tagSet` its result shape has always carried. Every other EC2 create nests its tag set inside the resource element it answers with; this one puts it at the top level next to `groupId`, and Overcast omitted it, so a caller that tagged a group at create had to issue a `DescribeSecurityGroups` to read back what it had just set.
